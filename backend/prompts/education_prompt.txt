BULLET NUMBERING RULES
=============================

Apply numbering to bullet points and list items in the document. These rules apply uniformly across ALL sections — Pupil_Views, Parent_Carer_Views, Strengths, Needs, Outcomes, etc.

IMPORTANT: The document text may come from Document Intelligence, which often STRIPS bullet markers (•, o, -) and indentation. You must use SEMANTIC understanding to detect the structure:
- A line that ends with a colon (:) and is followed by shorter, related lines = parent with sub-items.
- Lines that elaborate, list details, or give examples about the line directly above them = sub-items of that line.
- Lines that introduce a completely new, independent topic = new main bullet.
- An introductory sentence that just sets context before a list begins = unnumbered intro (not a bullet).

How to number:
- If a section begins with an introductory sentence before list items, return it as an unnumbered array element. Numbering starts at the first list item.
- Each main/independent point gets the next sequential number: 1, 2, 3...
- Sub-items underneath a parent get hierarchical numbering: parent.1, parent.2, parent.3...
- Deeper nesting continues: parent.sub.1, parent.sub.2...
- Numbering resets within each schema field.

How to identify sub-items when bullet markers are stripped:
- If a line ends with a colon (:), the lines that follow until the next independent topic are sub-items of that line.
- If several short lines follow a longer explanatory line and they all relate to it, they are sub-items.
- If a line could stand alone as an independent statement about a different topic, it is a new main item.

CRITICAL FORMAT RULE:
Each item and sub-item MUST be its own separate array element with its number prefix.
NEVER merge a parent and its sub-items into one string using \n.
This applies to ALL array fields: Strengths, Needs, Outcomes, Views — everything except Provision tables.

Abstract patterns showing the correct output format (note: input may have NO bullet markers since Document Intelligence strips them):

Input (plain text, markers stripped):

Second point about topic B:
Detail about B part 1.
Detail about B part 2.
Detail about B part 3.
Third point about topic C.

Correct output — "Second point about topic B:" ends with colon, so the detail lines after it are sub-items:
[
  "1 First point about topic A.",
  "2 Second point about topic B:",
  "2.1 Detail about B part 1.",
  "2.2 Detail about B part 2.",
  "2.3 Detail about B part 3.",
  "3 Third point about topic C."
]

WRONG — sub-items merged into parent with \n (NEVER do this):
[
  "2 Second point about topic B:\nDetail about B part 1.\nDetail about B part 2."
]

WRONG — sub-items have no number prefix (NEVER do this):
[
  "2 Second point about topic B:",
  "Detail about B part 1.",
  "Detail about B part 2."
]

WRONG — sub-items restart numbering at 1 instead of inheriting parent number:
[
  "2 Second point about topic B:",

Correct output:

  "5 Top-level point:",
